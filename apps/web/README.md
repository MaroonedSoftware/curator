# @curator/web

Browser UI over [`@curator/api`](../api/README.md): Vite, React 19, Mantine, TanStack Router and
TanStack Query, laid out like `ats/apps/web`.

## Running

```
pnpm --filter @curator/api dev   # the API on :14100
pnpm --filter @curator/web dev   # this app on :14102
```

Vite proxies `/api` to the API and strips the prefix, so the browser stays same-origin. A
production deployment needs the same: the API reachable at `/api` on the app's origin.

## Pages

| Path                 | Does                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `/`                  | Opens the TV this browser last looked at, else the first one, else `/tvs`                          |
| `/tvs`               | The stored TVs (rename, remove), and adding one: search the network or type its address, then pair |
| `/tvs/$tvId`         | Now showing: the artwork on screen, and an art-mode switch                                         |
| `/tvs/$tvId/library` | The TV's art by category (`?category=`), with Show on TV, Change matte and Delete                  |
| `/tvs/$tvId/upload`  | Drop a JPEG or PNG (up to 20MB), pick its mattes, and optionally show it at once                   |
| `/tvs/$tvId/status`  | The TV's address, model, power state and art API version                                           |

The header's TV picker switches TV and stays on the same page. A link to a TV that has been removed
says so and points back to `/tvs`.

The TV doesn't confirm most writes, so pages read its state back afterwards rather than trusting
the request. Delete is offered only for uploads (My Photos). Mattes are a style and a colour from
the lists the reference library documents; a matte that doesn't fit the image is refused by the TV.

There are no thumbnails yet: the frame client can't fetch them, so artwork is listed by content id.

## Layout

```
src/
  main.tsx               providers and the router
  api/                   api.client.ts (typed fetch: `api` for TVs, `tvApi(tvId)` for one TV's art), query options and keys
  tvs/                   the TV a page is about (`useTv()`), and the TV this browser last looked at
  routes/                TanStack file routes; routeTree.gen.ts is generated by the Vite plugin and committed
  components/            pages and pieces, one folder per area
tests/
  fake.api.ts            stubs fetch with a table of "METHOD /path" responders
  test.render.tsx        renders the real route tree at a path under the app's providers
```

TV failures surface as the API reports them (`src/api/api.error.ts`): unreachable, didn't answer,
refused, or rejected.
