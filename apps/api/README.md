# @curator/api

HTTP API over [`@curator/frame`](../../packages/frame/README.md), built on
[ServerKit Fastify](https://github.com/MaroonedSoftware/serverkit/tree/main/packages/fastify).

## Layout

```
src/
  index.ts               entry point: load config, start the server
  server/                config loading and validation, the plugin stack, buildServer/startServer
  modules/               ServerKit modules (DI registrations and lifecycle hooks), in setup order
    data/                Postgres through Kysely; kysely.ts is generated by `pnpm build:datatypes`
    frame/               the TV: the SamsungFrameClient, and FrameService, which routes call
  routes/                Fastify route plugins, schemas declared with zod
data/migrations/         dbmate migrations
scripts/with.database.url.ts   runs dbmate or kysely-codegen against the configured database
tests/
  test.db.ts             per-test-file databases, cloned from a template migrated once per run
  test.server.ts         builds the real server for app.inject(), with FakeFrameClient in place of the TV
  fake.frame.client.ts   an in-memory FrameClient
```

## Database

Postgres 17 from the root `docker-compose.yml`: `curator-db` on 14132 for development and
`curator-db-test` on 14133 (tmpfs) for the tests. `pnpm db:up` starts both.

```
pnpm migrate:up          # apply data/migrations to the configured database
pnpm migrate:create name # a new migration
pnpm build:datatypes     # regenerate src/modules/data/kysely.ts from the migrated schema
```

The test run migrates a template database once (`tests/setup.global.ts`) and every test file
clones its own, so tests never share rows. Edit a migration in place freely until it ships: the
template is rebuilt from scratch each run.

## Running

```
pnpm dev     # from apps/api: watch mode on :14100
pnpm build && pnpm start
```

Config is `appconfig.${NODE_ENV}.yaml` (default `development`), overlaid by a gitignored
`appconfig.local.yaml`. Any string value may be `${env:NAME}`. The whole tree is validated at boot
(`src/server/api.config.ts`), so a bad value fails with its key named.

Set the TV's address before the first run, in `appconfig.local.yaml`:

```yaml
tv:
    host: 192.168.1.50
```

or as `CURATOR_TV_HOST`. The first request that reaches the TV pops a pairing prompt on it; accept
it and the token is kept in `.data/tv-token.txt`. `tv.debug: true` logs every frame on the wire.

To run without a TV, start the fake one (`pnpm fake:tv` in `packages/frame`) and point the API at
it with `tv.host: 127.0.0.1` and `tv.port: 14180`.

There is no authentication: the API is meant for the home network the TV sits on.

## Routes

| Method | Path                            | Body / answers                                                        |
| ------ | ------------------------------- | --------------------------------------------------------------------- |
| GET    | `/health`                       | `{ status: 'ok', uptimeMs }`. Never touches the TV.                   |
| GET    | `/tv`                           | Device info: `{ model, name, frameTvSupport, powerOn, raw }`          |
| GET    | `/tv/api-version`               | `{ version }` of the TV's art API                                     |
| GET    | `/tv/art?category=`             | `{ items: [{ contentId, categoryId, raw }] }`                         |
| GET    | `/tv/art/current`               | `{ contentId, categoryId, raw }` for the artwork on screen            |
| GET    | `/tv/art-mode`                  | `{ on }`                                                              |
| POST   | `/tv/art?matte=&portraitMatte=` | Raw `image/jpeg` or `image/png` body, up to 20MB. 201 `{ contentId }` |
| PUT    | `/tv/art/current`               | `{ contentId, show?, category? }` selects it. 204                     |
| DELETE | `/tv/art/:contentId`            | Deletes it from the TV. 204                                           |
| PUT    | `/tv/art/:contentId/matte`      | `{ matte, portraitMatte? }`, e.g. `shadowbox_polar`. 204              |
| PUT    | `/tv/art-mode`                  | `{ on }`. 204                                                         |

Categories: `MY-C0002` uploads, `MY-C0004` favourites, `MY-C0008` the Art Store.

The TV often leaves writes unanswered, so a 204 means the request was sent, not that the TV acted
on it. Read the state back (`GET /tv/art/current`, `GET /tv/art-mode`) when it matters. A write the
TV explicitly rejects, such as a matte that doesn't fit the image, still answers 422.

Uploads are the exception: they wait for the TV to announce the new image, so a 201 carries the
content id it assigned.

```
curl -X POST 'localhost:14100/tv/art?matte=shadowbox_polar' -H 'content-type: image/jpeg' --data-binary @photo.jpg
```

### When the TV fails

| Status | Means                                                                     |
| ------ | ------------------------------------------------------------------------- |
| 503    | The TV is unreachable: asleep, off the network, or it closed the socket   |
| 504    | The TV took the request but never answered                                |
| 502    | Pairing was refused, or the TV sent something the client couldn't read    |
| 422    | The TV rejected the request (an unknown content id, an unsupported matte) |

`details.reason` carries the client's message.
